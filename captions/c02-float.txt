0.1 + 0.2 = 0.30000000000000004 in Python, JavaScript, C and everything else. It's not a bug. It's how floats work.

What's happening:
1. 0.1 in binary is 0.000110011001100… repeating forever, like 1/3 in decimal
2. A float64 stores 52 bits of digits, so the pattern is chopped and rounded. Stored 0.1 = 0.1000000000000000055511151…
3. 0.2 is a bit high too. Their exact sum lands between two floats and rounds up to the one above 0.3 → == says False
4. Every float = sign + exponent (scale) + mantissa (digits)

It's also why last episode's loop and NumPy disagreed in the last digits: they added in a different order, so they rounded differently.

The AI twist: models train in bfloat16, which has only 7 stored mantissa bits. π becomes 3.140625 (verified in PyTorch). Neural nets barely notice, and you get half the memory and much faster math. It keeps float32's 8 exponent bits, so it reaches ~3.4×10³⁸, while float16 overflows past 65,504.

Rule: never compare floats with ==. Use math.isclose().
